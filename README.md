# 动漫游戏活动日历

[简体中文](README.md) | [English](README_EN.md) | [日本語](README_JA.md)

> **本项目由 AI 编写**——从原型、前后端代码、爬虫内核、安卓 App,到每日活动排期的核实补录,全部由 AI 智能体(Agent)接力完成。

自动抓取各二次元游戏**官方公开接口**的活动排期与公告资讯,聚合成苹果(iOS)风格的**活动月历**(点任意一天查看当日排期)与活动列表,带倒计时与进度条。提供 **PC 网页版** 和 **安卓 App 版**。

## 功能一览

| 功能       | 说明                                           |
| -------- | -------------------------------------------- |
| 聚合 5 款游戏 | 崩坏:星穹铁道、绝区零、明日方舟:终末地、鸣潮、异环 + 各自官方 B 站号动态     |
| 双引擎数据    | 爬虫每 30 分钟抓官方接口保证实时性;AI Agent 每天联网搜索核实补录保证准确性 |
| 活动月历     | iOS 风格月历,点任意一天查看当天开始 / 进行中 / 当天结束的活动         |
| 图片排期识别   | 只发图片不发文字的排期(典型:终末地)用浏览器截图 + 多模态视觉识别录入        |
| 多端使用     | PC 网页 / 安卓 APK / PWA(「添加到主屏幕」,离线可看)          |
| 订阅与提醒    | ICS 日历订阅、飞书 / Bark 活动开始推送、Tailscale 外网访问     |
| 活动详情弹窗   | 列表带缩略图;点击弹出完整排期图、倒计时、官方链接                    |

## 安装与使用

<a id="android"></a>

### 安卓 App

安卓版为原生 WebView 壳,内置两种模式:**服务器模式**(连接电脑服务器,数据最全最准)与**爬虫模式**(应用内直接抓官方接口,无需电脑)。

**直接下载:** 从 [Releases](https://github.com/BBQMARTE/anime-game-calendar/releases) 下载 APK,传到手机安装(需允许安装未知来源应用)。

网页版右上角**齿轮设置**:一键开关日历视图;按游戏勾选是否显示在月历上(独立于列表筛选)。

**本机构建(已装好 SDK 到 D 盘):**

直接双击 `构建APK.bat`。首次运行会自动生成正式签名密钥(`android/ycal.keystore`,密码见 `android/keystore.properties`),产物在 `android/app/build/outputs/apk/release/app-release.apk`;若机器上没有 keytool,脚本会自动回退构建 debug APK。

> **务必备份** **`android/ycal.keystore`**:密钥丢失后无法对已安装的应用覆盖升级,只能卸载重装。

**其他机器构建:** 用 Android Studio 打开 `android/` 目录,同步后 `Build > Build APK(s)`。

最低支持 Android 8.0(API 26)。

> 安卓工程引用的页面资源在 `android/app/src/main/assets/www/`(是 `static/` 的副本)。
> **修改** **`static/`** **后,记得先复制到** **`android/app/src/main/assets/www/`** **再重新构建。**

<a id="pc"></a>

### PC 网页版(手动安装)

1. 安装依赖(首次):`pip install -r requirements.txt`
2. 双击 `启动.bat`(或运行 `python app.py`)
3. 浏览器自动打开 <http://127.0.0.1:5000>

- 启动后自动抓取一次,之后每 30 分钟自动刷新;也可点右上角刷新按钮。

- 抓取结果缓存在 `data/cache.json`,重启后立即恢复。

- 界面跟随系统深色/浅色模式自动切换。

局域网内其他设备(平板/手机)用 `http://<电脑IP>:5000` 访问;出门在外见下方[订阅与提醒](#notify)的 Tailscale 方案。

### 展示逻辑:真活动与资讯分级

所有抓取到的内容分为两级:

| 级别             | 内容                                                            | 展示位置      |
| -------------- | ------------------------------------------------------------- | --------- |
| **活动 (event)** | 限时活动、角色与专武卡池(祈愿/跃迁/调频/唤取/寻访申领)等**带起止时间**的排期,自动精简为短标题,带倒计时与进度条 | 进行中、即将开始  |
| **资讯 (info)**  | 修复公告、玩法说明、商城上新、问卷、官网新闻稿、B站动态                                  | 仅「全部资讯」页签 |

<a id="why"></a>

## 数据为什么准确:爬虫 + AI 双引擎

本项目最初是纯爬虫实现的:抓官方接口、拆版本说明文、正则解析时间区间,功能上跑通了。

但实际用起来,爬出来的数据错误百出——起止时间反转、正文片段被当成活动标题、官方接口偶发返回错误内容产生一堆垃圾条目……纯规则解析永远堵不完这些边角案例。

后来灵光一现:**Agent 软件不是有联网搜索能力吗?让 AI 每天替我去搜官方公告、核实排期,会怎么样?**

结果非常棒:Agent 搜出来的活动排期又准又全,时间精确到分钟,直接吊打爬虫的规则解析。日历里每一条 AI 核实条目都来自这条通道。

于是项目定型为**双引擎**:

| 引擎          | 频率      | 负责什么             |
| ----------- | ------- | ---------------- |
| 爬虫          | 每 30 分钟 | 自动抓取官方接口,保证实时性   |
| AI Agent 搜索 | 每天一次    | 联网核实补录活动排期,保证准确性 |

### AI Agent 每日自动化指令全文

数据准确性靠的就是下面这一条自动化指令。按[快速开始](#quickstart)把仓库链接发给 Agent,它会读到这一节,**自己创建定时任务**、自己填好项目路径——你什么都不用抄。

指令全文也附在下面,两种用途:① 供 Agent 直接取用;② 想手动设置的人,在 Agent 软件里新建每天一次的定时任务(如 20:00),把指令贴进去,`<项目路径>` 替换为本机仓库路径。

Agent 每天自动:确保服务在线 → 联网搜索核实新活动 → 识别图片型排期(浏览器截图法)→ 更新日历 → 清理过期条目。

```text
动漫游戏活动日历每日运维任务。项目目录:<项目路径>。严格按以下步骤执行,不要修改任何代码文件。

【第一步:确保本地服务在线】
访问 http://127.0.0.1:5000/api/events 探测服务;不可达则在项目目录后台启动 python app.py,等待约 10 秒再确认;服务已在线则跳过,绝不要重启已在运行的服务。

【第二步:联网搜索,核查 5 个游戏的新活动】
搜索以下游戏最近 1~2 天官方新发布的活动与卡池排期:
- 崩坏:星穹铁道(game_id: hsr)
- 绝区零(game_id: zzz)
- 明日方舟:终末地(game_id: endfield)
- 鸣潮(game_id: wuwa)
- 异环(game_id: ananta)
重点找:新版本「活动一览/更新说明」、限时活动、角色与专武卡池(祈愿/跃迁/调频/唤取/寻访申领)的起止时间。
核实标准:起止时间必须经官方来源交叉确认(官网新闻、官方B站号、游戏内公告转载);时间按北京时间精确到 HH:MM;无法核实的一律不录入,宁缺毋滥。

【图片型排期识别(浏览器截图法,不接任何第三方 API)】
部分游戏(典型:明日方舟:终末地)把活动排期做成图片发布,纯文字搜索抓不到。注意:WebSearch/WebFetch 只返回文字,图片从未进入模型上下文,模型再多模态也"看不见"。解决办法是用浏览器工具亲眼识图:
1. 从抓取缓存 data/cache.json 或搜索结果中找到「版本日历/活动一览」图片的直链 URL(hdslb.com、hycdn.cn 等图床,可从官方B站动态或官网提取)
2. 派浏览器子代理打开该图片(经本项目 /api/img 代理加载可绕过防盗链),截图后逐条转写图中所有活动的名称与起止日期;长图需滚动多次截图覆盖全图
3. 对转写结果做合理性校验(日期落在版本周期内、与已录入条目不矛盾)后按第三步录入,image 字段填该排期图 URL;图上读不出 HH:MM 的,按该游戏版本更新惯例时刻(终末地 12:00 更新、次日 11:59 结束)补齐并在汇报中注明
4. 若 Agent 平台没有浏览器/截图工具,退回纯文字搜索模式,在汇报中列出未能识别的图片 URL;绝不让模型臆测图片内容

【第三步:更新 data/manual.json】
1. 先完整读取该文件现有条目
2. 按(game_id + 标题)去重,已存在的不重复添加
3. 新增条目追加到 JSON 数组末尾,字段格式:
   {"game_id": "hsr", "title": "「活动名」", "category": "活动", "start": "2026-08-20T10:00", "end": "2026-09-03T03:59", "link": "官方链接", "image": "活动配图URL,可选"}
   image 填官方配图/排期原图的直链,用于列表缩略图与详情弹窗大图;无图留空字符串
   category 取值:活动 / 角色与专武 / 公告 / 资讯(角色、专武卡池一律用「角色与专武」)
   常驻或无结束时间的活动 end 填空字符串;只录入结束时间在当前之后的活动
4. 清理过期:删除所有 end 为有效日期且早于当前时间的条目;end 为空字符串的常驻条目保留
5. 以 UTF-8 保存,保证 JSON 数组格式合法

【第四步:触发服务刷新】
服务在线则向 http://127.0.0.1:5000/api/refresh 发 POST 请求,请求头带 X-Requested-With: ycal

【汇报】
简要汇报:① 服务在线状态;② 各游戏新录入的活动;③ 清理了多少条过期条目;④ 无新增的游戏直接说明「无新增」;⑤ 图片排期识别情况:识别了哪几张排期图、转写录入多少条、修正了哪些现有条目。拿不准时间的活动不录入,并明确说明存疑。
```

### 时间解析内核

活动时间的提取由 `timeparse.py`(网页/服务版)与 `static/scraper.js`(安卓端,同构)共用,已覆盖绝大多数真实公告写法:

- **日期**:`2026年7月10日` / `2026/07/10` / `2026.07.10` / `07.10` / `7月10日` / `7/10` / 全角数字

- **时间**:`12:00` / `12:00:00` / `12点` / `12点30分` / `12时30分`

- **区间**:`x月x日 ~ x月x日`(`~ ～ — –` 以及 `至` / `到` / `-` 均可)

  - 即使**没有**「活动时间:」之类关键词,只要出现紧挨的两个日期也会识别为区间

  - `12月30日 ~ 1月5日` 这类跨年区间会自动把结束日滚到下一年

- **长期/常驻**:含「长期/常驻/永久/持续开放」视为无结束的常驻活动

- **活动名**:支持 `「」『』【】[]（）〈〉` 多括号,以及 `■/◆/✦` 标题行;泛称(如「版本活动」)会被过滤

- **缺结束时间**:识别到开始时间但拿不到结束时间的活动,默认补 **2 天**窗口,保证日历有可见时长

<a id="manual-add"></a>

### 手动添加活动(兜底通道)

如果自动抓取漏了某个活动,有两种方式补录(上面「AI Agent 自动化」走的也是这条通道):

**方式一:自己填** —— 编辑 `data/manual.json`(数组格式,可加多条),下次刷新自动并入列表:

```json
[
  {
    "game_id": "ananta",
    "title": "「像素溢出」限时活动",
    "category": "活动",
    "start": "2026-08-01T10:00",
    "end": "2026-08-15T04:00",
    "link": "https://yh.wanmei.com/",
    "image": ""
  }
]
```

- `game_id` 可选:`hsr / zzz / endfield / wuwa / ananta`

- `category` 可选:`活动 / 角色与专武 / 公告 / 资讯`

- 手动填入的条目默认视为活动(kind=event)直接进入「进行中/即将开始」,带灰色「手动」标签。

- 安卓端:在应用内 localStorage 的 `ycal_manual` 键写入同样格式的 JSON 数组。

**方式二:发图/发文给 AI 代填** —— 把官方发布的版本活动排期图(如「异环1.2活动日历」)或活动文字直接发给 AI 助手,助手读取内容后帮你写入 `data/manual.json`;排期图可让 AI 一并识别,并把原图 URL 填入 `image` 字段(列表显示缩略图,点击活动弹出完整大图与文字详情)。
